1 · 图实例

2 · 点

每个点都自带 id（索引固定为 0，类型由图实例的 id 类型决定）—— id、createdTime、lastUpdatedTime 不能当属性名。

3 · 边

每条边也自带 id，另有 source/target 两个端点； 最大出入度只对 -Edge 存储有意义（其它存储里字段会置灰）。

5 · 造数据（可选）

      
先保存并加载，再往这张图里写点和边；写完可以直接查。属性列来自当前 schema，
        保存后会自动跟着更新。写入一个已经存在的 id 会先提示（合并写入，不是新建）。

      

        
        
      

      

      
      

      

        
        
      

      

        
        
      

      

      
      

    


    

      
5b · 从 CSV 导入

      
表头就是列名：点和边都要有 id，边还要有 source 与
        destination，其余列按 schema 里的属性名对应（多出来的列会被忽略，缺的属性列会提示）。
        导入前会先确认，按每 200 行一批写入。

      

        
        
      

      

      

        
        
      

      

    


    

      
5c · 删除已写入的数据

      
删除是低层操作：点删掉后它的边不会跟着消失（对端会留下悬空边）；边存在于两个端点，
        删除时要给出与写入时相同的起点/终点。每次都先确认代价。

      

        
        
      

      
      

      

        
        
      

      

        
        
      

      
    


    

      
6 · 模糊关联模式

      
模式把 context 的片段拼成一个 key（邮箱域名、IP 前缀、卡 BIN、正则截取……），
        片段相同的账户就会落在同一个 FuzzyLink 节点上。模式属于图，存在工作目录的 fuzzy-patterns.json 里，
        保存后下一次查询立刻生效。
